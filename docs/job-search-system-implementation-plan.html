Personal job search system · implementation plan

01 / Outcome and scope

What this system should accomplish

A useful first release should make every application easy to record, every follow-up visible, and repeated application questions quick to answer. You will find roles yourself on LinkedIn, Wellfound, and company career portals. The system begins when you choose a role.

1

Application tracker

One Google Sheet is the source of truth for roles, stages, next actions, follow-ups, and resume versions.

2

Application assistant

Codex uses verified career facts and a pasted job description to recommend a resume and prepare truthful, tailored answers.

3

Chrome form helper

A click-to-fill helper handles recurring fields on supported company portals, shows a review, and leaves final submission to you.

Known inputsTarget roles: Software Development Engineer, Frontend Engineer, Backend Engineer, Full Stack Developer, AI Engineer, and MERN Developer. Planned final working day: 11 November 2026. Planned availability: 12 November 2026, unless an earlier release is confirmed.

The first release focuses on application preparation and tracking. Job discovery remains a manual choice, so this plan does not depend on scraping or a job-board feed.

02 / System design

One pipeline, three connected modules

Choose job→Paste job description→Prepare answer pack→Review / apply→Update Sheet→Follow up
Integration goalEach role has one Application ID. The assistant uses that ID to prepare a resume recommendation and answer pack; the Chrome helper uses the approved pack to fill supported company forms; the Sheet records the actual submission and next action. These are modules of one workflow, not three independent products.
LayerOwnsImplementation
Google SheetApplication records, next actions, verified profile facts, answer templates, resume catalogueTabs, validation, formulas, conditional formatting, and a small bound Apps Script menu/sidebar
Codex workflowJob-description analysis, resume selection, answer drafts, evidence and missing-information flagsA reusable instruction template plus a structured candidate profile derived from the four resumes
Chrome helperUser-invoked field detection, preview, and filling on approved company application pagesManifest V3 extension with temporary activeTab access and minimal permissions

First usable version: the Sheet, Codex workflow, and Chrome helper share the Application ID and exported profile/answer-pack files. You review and move approved answers between them. This avoids a hosted server or AI API key while we validate real applications. Integrated version: the Chrome side panel reads and writes the Sheet with authorized access and calls an AI service through a protected backend, eliminating the manual transfer. Codex can build that integration after the first version proves the data model and form mappings.

Shared data contracts

The Sheet assigns one stable applicationId per role. The approved profile export contains versioned facts[], resumeVersions[], and standardAnswers[]. Each job-specific answer pack contains applicationId, resumeVersionId, answers[], and the IDs of the facts used to draft each answer. Version numbers let the assistant and extension warn when their imported copy is older than the Sheet.

Data boundaryResume facts and saved answers should contain only information you have verified. The extension should never store site passwords, session cookies, government IDs, or payment details. Sensitive self-identification questions stay for your own review.

03 / Deliverable one

Google Sheets application tracker

The tracker should be usable before the assistant or extension exists. Enter a role in under a minute, then use a daily view to see what needs attention.

Workbook structure

TabPurposeKey behavior
ApplicationsCanonical row per company and roleDropdown status and role family; filters; protected ID/formula columns; clickable job link
TodayAction queueShows due or overdue follow-ups, active interviews, and applications still being prepared
Profile & AnswersReusable verified facts and answer templatesEach fact has source, verification state, and last-reviewed date
DashboardWeekly reviewCounts by stage, applications by week, interviews, and overdue actions

Applications data model

Field groupColumnsRules
IdentityApplication ID, company, title, role family, source, job URL, locationGenerate an ID; warn on a duplicate URL or the same company + title
ProgressDate saved, date applied, status, last updated, next action, due dateUse fixed statuses and real dates; a due date belongs to an action, not to a status
Application recordResume version, answer-pack link or ID, recruiter/contact, notesRecord which PDF and answers were actually submitted
OutcomeResponse date, interview date, outcome/reasonKeep rejection and withdrawal distinct; do not overwrite prior applications

Status set: Saved → Preparing → Applied → Assessment → Interview → Offer, with Rejected and Withdrawn as terminal states. “Follow-up due” is a calculated view, not a separate status.

Interaction and automation

  • A bound Apps Script menu opens a compact Add application form and an Update status form. Google documents menus, dialogs, and sidebars as supported Sheet extensions.
  • Apps Script functions handle addApplication, updateApplication, getDueActions, and exportApprovedProfile. The sidebar validates required fields before writing a row.
  • Conditional formatting highlights overdue actions and upcoming interviews. Data validation prevents accidental status spelling variants.
  • New applications can start with a suggested follow-up date; the date remains editable because different recruiters and stages need different timing.
  • Email-based status suggestions are a later enhancement. They require a separate decision about inbox access and should never silently mark a rejection or interview.

Success condition: a new application is recorded in less than one minute, and the Today tab reliably shows the next action for every active application.

04 / Deliverable two

Resume-grounded application assistant

The assistant turns your existing resumes into a verified fact bank, then drafts an answer pack for a job description you paste. It should make a suggestion and show the evidence behind it; your review decides what is sent.

Candidate profile and resume catalogue

Role familyStarting variantEvidence to lead with
General SDE / backendSDE; Python variant where FastAPI is centralEnterprise privacy module, backend services, access controls, Java/Spring Boot or FastAPI, DSA
MERN / full stackMERNReact + Node/Express + MongoDB, Jira plugin, PayPocket, end-to-end product delivery
FrontendMERN initially; create a dedicated frontend variantReact UI, task/calendar workflows, responsive interfaces, AI chat frontend
Applied AI EngineerSDE or startup variant initially; create a dedicated applied-AI variantTechMateAI, RAG, LangChain, ChromaDB, PingAI and streaming AI chat
Startup full stackStartup variantOwnership, fast MVP delivery, cross-stack implementation, customer-facing product work

The common DSA proof point is 1100+ LeetCode problems, a 1712 maximum rating, and contest rank 1855, as stated in the provided resumes. The profile must record these as resume claims to verify, not as automatically refreshed statistics.

Fact record format

Each reusable claim should store fact ID, claim, source resume / experience, verified?, approved wording, and last reviewed. Contact details, work authorization, salary expectations, and availability are separate fields. The UPAAV date stays “Present” until the actual end date; future applications can state the planned 12 November availability.

Per-job input and output

Input you provide

Job title, company, portal, URL, pasted job description, location, and any application questions. Pasting avoids a dependency on reading job-board pages.

Output you review

Recommended resume, 3–5 matching proof points, a concise role pitch, draft answers within requested character limits, and a list of unknown or unsupported items.

Generation rules

  1. Choose the resume by role evidence, not by title alone; ask for a new tailored version when the existing four are weak fits.
  2. Use only verified profile facts. Keep the source fact beside each proposed answer during review.
  3. Preserve exact company names, employment dates, technologies, and metrics. Never invent years of experience or production ownership.
  4. Mark custom questions that need your judgment: salary, relocation, sponsorship, start date exceptions, demographic information, or personal motivation.
  5. Save the approved answer pack under the Application ID so the tracker records what you sent.

Files to implement: a human-readable candidate profile, a reusable Codex instruction template, and a structured answer-pack template. The first build should also create two focused resume variants for frontend and applied-AI roles after the underlying claims are verified.

Success condition: an answer pack is useful without factual corrections in a pilot set of five real job descriptions, with any unknown clearly marked.

05 / Deliverable three

User-invoked Chrome form helper

The helper targets repetitive form entry on company career portals. It should be small and predictable: identify supported fields, propose values, show a preview, fill after a click, and stop before submission.

Open company form→Click extension→Preview matches→Fill selected fields→Inspect form→You submit

Release-one fields

Fill automatically after reviewPrompt for manual action
Name, email, phone, location, LinkedIn/GitHub/portfolio links, education, planned availabilityResume file upload, CAPTCHA, login, employer-specific legal declarations
Selected approved answers from the current job's answer packSalary, sponsorship, demographic or disability questions, and any answer lacking a verified fact

Technical design

  • Use a Manifest V3 extension with activeTab, scripting, and local storage. Access begins only when you click the helper on the current tab. Avoid blanket access to every site.
  • Keep a domain allowlist for tested company portals. Disable page interaction on LinkedIn and Wellfound; use the answer pack for manual review and paste there.
  • Use field labels, names, and nearby text to map inputs; never infer from position alone. Show a field-by-field preview with confidence and an “unmatched” list.
  • Do not overwrite a non-empty field without an explicit choice. Never click Apply, Submit, Send, or any equivalent final action.
  • Import a small approved profile export from the Sheet for the first release. A later release can use Google OAuth and the Sheets API for direct synchronization if manual import proves burdensome.
  • Support one or two recurring company portal form patterns first; expand only after real examples and site-specific review.

Extension modules: manifest.json for permissions, a popup or side panel for preview, a field mapper for common inputs, a content script for filling selected values, local profile storage, and a domain policy that blocks unsupported sites. Test the mapper against a local sample form before trying a live portal.

Platform boundaryLinkedIn states that third-party extensions that scrape, modify, or automate activity on its site are prohibited. Wellfound restricts automated collection and high-load automated access. For these platforms, use native features plus prepared answers outside the page. Review each company portal's terms before enabling the helper there.

Success condition: on a supported test form, the helper fills common fields accurately, flags uncertain fields, leaves existing entries intact, and cannot submit the application.

06 / Everyday use

The application loop

  1. Find and choose: browse LinkedIn, Wellfound, or a company careers page yourself. Save the URL and paste the description into the assistant.
  2. Prepare: review the recommended resume and answer pack. Resolve unknowns and select the PDF you will upload.
  3. Apply: use native browser or platform autofill where available. On supported company portals, invoke the Chrome helper for common fields and inspect the completed form before submitting.
  4. Record: add or update the row in Google Sheets with the actual submission date, resume version, status, and next action.
  5. Review daily: open Today for follow-ups, assessments, and interviews. Review Dashboard once a week to see which role families produce replies.

For a role that redirects from LinkedIn or Wellfound to a company portal, record the original source in the Sheet and use the company portal's final application URL as the job link. One Application ID follows the role through every stage.

07 / Build order

Deliver useful pieces in sequence

Phase 0
Profile audit

Verify the fact bank

Confirm employment dates, metrics, project claims, links, contact details, and planned availability. Identify the missing frontend and applied-AI resume variants. Output: approved candidate profile and resume catalogue.

Phase 1
Tracker MVP

Make the Sheet usable immediately

Create the four tabs, dropdowns, duplicate warnings, Today view, dashboard, and add/update menu. Enter a few existing applications to validate the workflow. Start logging live applications at this point.

Phase 2
Assistant MVP

Prepare role-specific answers

Write and test a repeatable Codex instruction template, fact matching, answer bank, resume recommendation, and answer-pack format using five real job descriptions.

Phase 3
Chrome helper

Fill recurring company forms

Implement a click-to-run extension on a local test form, then pilot one or two approved company portal patterns. Add preview, no-overwrite, no-submit, and domain-blocking checks.

Phase 4
Refine

Improve from real use

After about ten applications, inspect time spent, recurring questions, form mismatches, and missed follow-ups. Add only the automations that address measured friction.

08 / Acceptance checks

What “ready to use” means

  • Five sample applications can be entered, updated, filtered, and found again; duplicate detection catches a repeat URL.
  • Today shows an overdue follow-up, a due-today action, and an upcoming interview correctly.
  • The assistant recommends sensible resume variants for SDE, MERN, frontend, backend, and applied-AI sample roles.
  • Every drafted experience claim maps to an approved profile fact; unanswered questions remain visibly unanswered.
  • The Chrome helper fills known fields on a test form, does not overwrite existing values, and leaves uncertain fields for review.
  • The Chrome helper is inactive on LinkedIn and Wellfound and has no action that submits an application.
  • A completed application records the date, submitted resume, final status, and next action in the Sheet.
